## 3. Теоретические основы

### 3.1. Структура и логический порядок выполнения SELECT
В синтаксисе SQL порядок записи секций запроса отличается от логического порядка их выполнения ядром СУБД:

1. **Синтаксический порядок записи:**
   `SELECT` $\to$ `FROM` $\to$ `WHERE` $\to$ `GROUP BY` $\to$ `HAVING` $\to$ `WINDOW` $\to$ `ORDER BY` $\to$ `LIMIT / OFFSET`
2. **Логический порядок исполнения:**
   1. `FROM` (включая `JOIN`) — определение источников строк и соединение таблиц.
   2. `WHERE` — построчная фильтрация исходных кортежей предиката.
   3. `GROUP BY` — деление оставшихся строк на группы.
   4. `HAVING` — фильтрация агрегированных групп.
   5. `SELECT` — вычисление выражений, применение псевдонимов (`AS`), проекция столбцов.
   6. `DISTINCT` — исключение дубликатов.
   7. `ORDER BY` — упорядочивание результирующего набора.
   8. `LIMIT / OFFSET` — ограничение числа возвращаемых строк.

Следствие: псевдоним столбца, заданный в секции `SELECT`, **недоступен** в блоке `WHERE` (так как `WHERE` исполняется раньше `SELECT`), но доступен в `ORDER BY`.

### 3.2. Трехзначная логика (3VL) и значение NULL
В реляционной теории значение `NULL` означает отсутствие значения (неизвестно или неприменимо). Любое прямое сравнение с `NULL` (`x = NULL`, `x <> NULL`, `NULL = NULL`) возвращает логическое состояние **`UNKNOWN`** («неизвестно»). В секцию `WHERE` проходят только строки, для которых условие строго истинно (`TRUE`). Строки с `UNKNOWN` и `FALSE` отсекаются. Для проверки на отсутствие значения используются операторы `IS NULL` и `IS NOT NULL`, а также функция `COALESCE(val1, val2, ...)`.

### 4.1. Наполнение базы данных тестовыми данными
Для генерации более 1000 строк в крупных таблицах и согласованных связей использовалась функция `generate_series()` в комбинации с псевдослучайными и детерминированными формулами.

```sql
-- Пример генерации 1200 товаров (products):
INSERT INTO products (seller_id, category_id, title, description, price, is_active, created_at)
SELECT
    ((g % 20) + 1) AS seller_id,
    6 + (g % 15) AS category_id,
    'Товар категории ' || (6 + (g % 15)) || ' #' || g AS title,
    CASE WHEN (g % 7 = 0) THEN NULL ELSE 'Оригинальный сертифицированный товар...' END,
    ROUND((500.00 + ((g * 137) % 85000))::numeric, 2) AS price,
    (g % 20 != 0) AS is_active,
    NOW() - ((g % 180) || ' days')::interval AS created_at
FROM generate_series(1, 1200) AS g;
```

```sql
SELECT DISTINCT
    category_id AS "Код категории",
```

### 4.4. Запрос 3: Применение предикатов BETWEEN, IN, LIKE/ILIKE, IS NULL

#### А. Предикат BETWEEN (диапазонная выборка)
```sql
SELECT id AS order_number, user_id, status, total_amount
FROM orders
WHERE total_amount BETWEEN 10000.00 AND 30000.00
ORDER BY total_amount DESC
LIMIT 5;
```
*Результат:* заказы с суммой строго от 10 000 до 30 000 руб. включительно.

#### Б. Предикат IN (проверка вхождения в список)
```sql
SELECT id AS order_number, status, created_at
FROM orders
WHERE status IN ('processing', 'shipped')
ORDER BY created_at DESC
LIMIT 5;
```
*Результат:* отобраны только заказы в стадии обработки или доставки.

#### В. Предикат ILIKE (поиск по шаблону без учёта регистра)
```sql
SELECT id AS product_id, title, price
FROM products
WHERE title ILIKE '%pro%'
ORDER BY price DESC
LIMIT 5;
```
*Результат:* найдены модели «AirSound Pro», «ThinkPad X Pro», «Pixel Pro».

#### Г. Предикат IS NULL (проверка отсутствия значений)
```sql
SELECT id AS unmoderated_id, title, category_id,
       COALESCE(description, '--- ОПИСАНИЕ НЕ ЗАПОЛНЕНО ---') AS description_status
FROM products
WHERE description IS NULL
ORDER BY id ASC
LIMIT 5;
```
*Результат:* обнаружены строки с пропущенным описанием для последующей модерации.

#### Д. Комплексный запрос (объединение всех 4 предикатов):
```sql
SELECT id, category_id, title, price
FROM products
WHERE category_id IN (6, 7, 8, 9, 10)
  AND price BETWEEN 5000.00 AND 75000.00
  AND title ILIKE '%pro%'
  AND description IS NOT NULL
ORDER BY price ASC;
```

## 5. Ответы на контрольные вопросы

### 1. Из каких секций состоит команда SELECT и в каком порядке они логически выполняются?
Команда `SELECT` состоит из секций: `SELECT`, `FROM`, `WHERE`, `GROUP BY`, `HAVING`, `WINDOW`, `ORDER BY`, `LIMIT / OFFSET`.  
Логический порядок их обработки СУБД:
1. `FROM` (+ `JOIN`) — выбор и соединение таблиц;
2. `WHERE` — фильтрация строк;
3. `GROUP BY` — группировка строк;
4. `HAVING` — фильтрация полученных групп;
5. `SELECT` — формирование выражений проекции и псевдонимов;
6. `DISTINCT` — исключение одинаковых строк;
7. `ORDER BY` — сортировка итогового набора;
8. `LIMIT / OFFSET` — ограничение объёма выборки.

### 2. Почему в промышленных запросах не рекомендуется использовать SELECT *?
Использование `SELECT *` запрещено в production-разработке по следующим причинам:
- **Производительность сети и ввода-вывода:** пересылаются ненужные столбцы (включая тяжёлые типы `TEXT`, `BYTEA`, `JSONB`), что увеличивает сетевой оверхед и нагрузку на память.
- **Потеря индексного сканирования (Index Only Scan):** если запрашиваются конкретные столбцы, PostgreSQL может прочитать их прямо из B-tree индекса. `SELECT *` принудительно требует считывания страниц таблицы (Heap Fetch).
- **Хрупкость кода приложения:** при изменении схемы таблицы (добавление, удаление, перестановка столбцов) клиентские ORM и мапперы данных ломаются либо возвращают непредвиденные поля.

### 3. Для чего предназначена секция WHERE и как в ней комбинируются условия?
Секция `WHERE` отбирает строки, удовлетворяющие логическому предикату (значение выражения должно быть `TRUE`).  
Условия комбинируются операторами:
- `AND` (логическое «И», конъюнкция) — истинно, если оба операнда истинны;
- `OR` (логическое «ИЛИ», дизъюнкция) — истинно, если хотя бы один операнд истинен;
- `NOT` (отрицание) — инвертирует булево значение.  
Приоритет: `NOT` имеет наивысший приоритет, затем `AND`, затем `OR`. Для явного управления приоритетом обязательно применяются круглые скобки `(...)`.

### 4. Чем предикаты BETWEEN и IN отличаются от записи тех же условий через операторы сравнения и OR?
- `BETWEEN a AND b` семантически эквивалентен записи `(x >= a AND x <= b)`. Преимущество `BETWEEN` — лаконичность и наглядность. Особенность: границы $a$ и $b$ всегда включаются в диапазон.
- `IN (v1, v2, ...)` эквивалентен цепочке `(x = v1 OR x = v2 OR ...)`. Преимущество: запись компактнее, а планировщик PostgreSQL оптимизирует `IN` в операцию `ScalarArrayOpExpr` (хэш-поиск или проверку по массиву), что работает быстрее длинной цепочки дизъюнкций `OR`.

### 5. Как работает оператор LIKE и что означают символы % и _ в шаблоне?
Оператор `LIKE` сопоставляет строку с текстовым шаблоном с учётом регистра:
- `%` (процент) — заменяет любую последовательность символов любой длины (включая пустую строку);
- `_` (подчёркивание) — заменяет ровно один любой символ.  
В PostgreSQL оператор `ILIKE` выполняет аналогичное сопоставление, но без учёта регистра символов.

### 6. Что такое трёхзначная логика и почему нельзя проверять значение на NULL оператором «=»?
В SQL принята трёхзначная логика Лукасевича (Three-Valued Logic, 3VL), оперирующая тремя истинностными значениями: `TRUE`, `FALSE`, `UNKNOWN`. Значение `NULL` представляет неизвестность. Сравнение неизвестного с чем угодно (даже с другим неизвестным): `NULL = NULL` даёт `UNKNOWN`, а не `TRUE`. Так как предикат `WHERE` пропускает только строки со значением `TRUE`, выражение `WHERE col = NULL` всегда будет отсекать 100% строк. Проверка должна выполняться операторами `IS NULL` или `IS NOT NULL`.

### 7. Что делает секция ORDER BY и как задать сортировку по убыванию и положение NULL?
Секция `ORDER BY` сортирует строки результата по одному или нескольким полям:
- `ASC` — по возрастанию (по умолчанию);
- `DESC` — по убыванию.  
Положение неопределённых значений `NULL` регулируется модификаторами:
- `NULLS FIRST` — помещает значения `NULL` в самое начало списка;
- `NULLS LAST` — помещает значения `NULL` в самый конец списка (поведение по умолчанию для `ASC` — `NULLS LAST`, для `DESC` — `NULLS FIRST`).

### 8. Для чего служат LIMIT и OFFSET и как с их помощью организовать постраничный вывод?
- `LIMIT N` задаёт максимальное количество возвращаемых строк.
- `OFFSET M` указывает количество начальных строк, которые нужно пропустить.  
Для страницы с номером $P$ (начиная с 1) и размером страницы $S$ формула смещения:
$$\text{OFFSET} = (P - 1) \times S, \quad \text{LIMIT} = S$$
*Важное требование:* постраничный вывод корректен и детерминирован только при наличии явного и уникального порядка `ORDER BY` (например, по первичному ключу `id`). Без него порядок строк не гарантируется физической организацией страниц таблицы.

### 9. Что делает ключевое слово DISTINCT?
Ключевое слово `DISTINCT` исключает из результирующего набора строки-дубликаты, оставляя только уникальные комбинации выбранных столбцов. Выполняется после формирования проекции `SELECT` и требует операции сортировки (`Sort Unique`) либо хэширования (`HashAggregate`), что может быть ресурсоёмким на больших объёмах данных. В PostgreSQL также поддерживается расширение `DISTINCT ON (col1, col2)`, возвращающее ровно одну первую строку для каждого уникального набора значений указанных столбцов.

### 10. Как сгенерировать большой объём тестовых данных средствами PostgreSQL?
Для генерации больших массивов данных в PostgreSQL используются:
1. `generate_series(start, stop [, step])` — формирует виртуальную таблицу с последовательностью чисел, дат или меток времени.
2. Встроенные генераторы случайных величин: `random()` (вещественное число от 0 до 1), `md5(random()::text)` (случайные хэш-строки), операции со случайным выбором из массивов `(ARRAY['A', 'B', 'C'])[1 + floor(random() * 3)::int]`.
3. Конструкция `INSERT INTO ... SELECT ... FROM generate_series(...)`, позволяющая вставлять миллионы строк за секунды без написания внешних скриптов.
